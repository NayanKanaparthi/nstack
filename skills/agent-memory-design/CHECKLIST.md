# Checklist

The checks a memory system built with this skill must pass. Lines 1 to 24 came with v0.1. Lines 25 on were added in v0.2: each names the property of the agent it depends on, and is `n/a` when the agent does not have it. The reviewer is a separate Claude that did not see the design conversation or the build. See `steps/5-review.md` for how the review runs.

Every line is answered `yes`, `no` or `n/a`.

**When a line is `n/a`.** Run `scripts/check_design.py` on the design file. When it finds no problems it prints "CHECKLIST LINES THAT CANNOT APPLY to this design", with the reason for each. Those lines, and only those, are `n/a`, once you have confirmed the reason against the project. An agent with no side effects has no crash test to pass. An agent whose only store is the run log has its expiry tested under line 8, not line 10. A line the script did not list applies, even if the answer looks obvious. `n/a` counts as passing, so a review of a small agent can end.

**In a review of an existing agent** (`steps/review-existing-agent.md`) a line may also be answered `unknown`, when the code does not settle it either way. The answer says what would settle it. An `unknown` is not a pass and not a gap. Line 24 is `n/a` there.

**Which tests a line needs.** Where a line names several cases, each case is its own test. `steps/3-design.md`, section 9, is the one list of the cases and of when each applies, and the script counts them.

"Script" says what `scripts/check_design.py` checks for a line. It checks only that the design file is complete and agrees with itself. The reviewer still judges every line. The script's messages carry tags like `[check 5]` that point to the numbers here.
