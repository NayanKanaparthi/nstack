# agent-memory-design v0.2: review record

Version 0.2 was built in five parts. Each part was reviewed on a frozen copy by a separate Claude that never saw it built. The reviewer judged it against the v0.2 contract, the part's build spec and a list of lessons drawn from v0.1's reviews. A part that failed went back to the same builder, and the same reviewer checked the fixes. Then the parts were merged and the merged build was reviewed as a whole. All of it ran on 19 November 2026, New York time.

## The review path on a fixture with planted gaps

The contract asks that the review path, run on an agent with planted gaps, finds every planted gap and invents none on a clean version of the same agent.

- First run, on the review part's own copy: 7 of 8 planted gaps found as gaps. The 8th was seen and named in place, and could not be listed, because its checklist line came with the production part.
- Run on the merged build: PASS. On the planted version, 8 of 8 gaps listed. On the clean version, no gap invented by the answer key's rules. One real fault in the clean version, which the key notes but did not plant, was not found. The reviewer noted two limits of the run: four clean gaps were decided by the key's rule for gaps not on its list, applied by the same reviewer, and both versions were reviewed in one session.

## The merged build

The final review passed. No finding blocks the pull request. It made 12 findings, all follow-ups: 3 medium and 9 low. It said two of the medium ones should be fixed before the end-to-end build: a crash point the reviewer is told to try and the builder was not told to cover, and new places that hold data outside the delete, secrets and expiry rules. The third medium one, a wider meaning of "run", was Nayan's to decide. The review covered everything in the contract except the end-to-end sample agent, which comes in a second pull request.

## Limits accepted along the way

- A number with no word after it counts as held when the same digits stand anywhere in section 10 outside a source. Structure cannot do better without a word to match, and the reviewer still reads each rule. The reviewer asked for one line in the skill README's known limits.
- The extraction test set does not get a row from every kind of fact a model reads. Nayan chose to state the limit, and the check of that decision found it in the facts reference file, in the skill README's known limits, and in a list the checker gives the reviewer.
- A record changed after its task has acted can miss its next task. The reviewer agreed this is a limit and not a failure: the harm is one missing follow-up, not a wrong send.
- The worked example never shows a fact with no end date. The coordinator accepted this before the build.
- The code sketches' twin tests fake a disputed fact in two different ways, so no test passes a fact marked disputed by one sketch into the other.
